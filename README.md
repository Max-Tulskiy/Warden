# Warden — АРМ администратора информационной безопасности

Комплекс автоматизированного рабочего места администратора информационной
безопасности для противодействия инсайдерской активности внутри защищаемого
периметра. Агент на рабочих станциях непрерывно наблюдает за станцией и по
запросу сервера отдаёт данные за указанный промежуток времени; сервер
централизованно хранит и отображает полученные сведения.

> Полный список принципов, границ и принятых решений —
> [.specify/memory/constitution.md](.specify/memory/constitution.md).
> Архитектура и руководство — [docs/ru/](docs/ru/README.md)
> (English: [docs/en/](docs/en/README.md)).

## Что решает продукт

| Функция задания | Как реализована |
|---|---|
| Аппаратное и установленное ПО рабочей станции | `agent/src/warden_agent/collectors/inventory` → сервер хранит снапшоты и выявляет изменения |
| Подключаемые носители | `agent/src/warden_agent/collectors/removable_media` |
| Документы, отправляемые на печать | `agent/src/warden_agent/collectors/printing` |
| Запущенные процессы | `agent/src/warden_agent/collectors/processes` |
| Открываемые веб-сайты | `agent/src/warden_agent/collectors/web` |
| Предоставление данных за окно по запросу сервера (не более 4 часов) | Очередь задач на сервере + опрос агентом (модель активного агента) |
| Отображение и хранение отчётов за день | `server/` + веб-панель (`web/`) |
| Отдельное хранение сведений об оборудовании и ПО для выявления изменений конфигурации | `inventory_snapshots` + `inventory_changes` на сервере |

## Архитектура

```
Рабочая станция (Win10/11, Linux)          docker-compose
┌─────────────────────────────┐     ┌───────────────────────────┐
│ warden-agent (служба)       │     │ FastAPI ── PostgreSQL      │
│  коллекторы → буфер SQLite  │────▶│ обратный прокси (TLS)      │
│  (только исходящий HTTPS)   │     │ веб-панель (React)         │
└─────────────────────────────┘     └───────────────────────────┘
```

Агент — активный (по образцу Zabbix): сам инициирует связь с сервером,
периодически опрашивает список задач и выполняет их; сервер никогда не
подключается к агенту напрямую. Подробности — `docs/ru/architecture.md`.

## Сборка и запуск

```bash
# сервер, база данных, веб-панель
docker compose up --build

# агент — для разработки, из исходников
cd agent && pip install -e ".[dev]"
python -m warden_agent --config ./config.example.toml
```

Готовые установщики агента (`.msi` для Windows, `.deb`/`.rpm` для Linux)
собираются по тегу версии в GitHub Actions — см. `.github/workflows/release.yml`
и `docs/ru/usage.md`.

## Разработка через спецификации

Проект ведётся через спецификации (spec-driven development). Новая возможность
проходит цикл `/specify` → `/plan` → `/tasks` → `/implement`; спецификации
хранятся в `specs/NNN-имя/`.

```
.specify/memory/constitution.md         принципы, структура, решения
.specify/templates/                     шаблоны spec / plan / tasks
.claude/commands/                       команды цикла для Claude Code
specs/001-agent-server-complex/        базовая спецификация комплекса
contracts/openapi.yaml                  контракт API — источник правды
```

Конституция имеет приоритет над остальными договорённостями: код или план,
противоречащий ей, исправляется — либо она меняется по процедуре её раздела VII.

## Предупреждение

Комплекс не перехватывает сетевой трафик и не восстанавливает содержимое
напечатанных документов — только метаданные. Полный список границ — раздел V
конституции и `docs/ru/architecture.md`.
